to_dict()[source]#

Return the documented, stable JSON shape of this resolution.

The keys, in order: schema_version (int), repository (owner/repo), mise_version, recommendation (the first candidate’s backend string, or null), candidates (best first, each with backend_string, recommended, tier (int), legacy (bool), warning (text or null), command and reasons), excluded (each with backend_string and reason), platform (os-arch or null) and notes (a list of text).

command is always a string. It names the registry short name for the backend mise itself picks first for a registry entry (so the entry’s options, which mise registry --json omits, apply), and the explicit backend string for every other candidate; backend_string stays the candidate’s identity either way. An argument that needs quoting is quoted for the target platform’s shell: double quotes for a Windows target, POSIX single quotes otherwise.

Returns:

A structure that json.dumps accepts.

Returns:

The ranked candidates; the first is the recommendation.

When GitHub is unreachable or a mise probe fails, the other candidates are kept and the skipped steps are named in notes.

The first failure (GitHubUnavailableError or MiseError) is raised instead when a step failed and no step found a candidate, so the answer does not read as “no backend”.

An InvalidPlatformError is raised when no platform is given and the host is not a supported platform; an explicit platform needs no host detection.

The mise adapter: the only code that runs a mise binary (ADR 0002).

mise always runs in an isolated environment so the user’s settings, such as MISE_DISABLE_BACKENDS, never change the answer: a clean environment, a temporary HOME, MISE_NO_CONFIG=1, and GITHUB_TOKEN plus the proxy and certificate variables passed through so mise can still reach the network, and SystemRoot, which Windows needs in an explicit environment.

Set up logging for the project.

This module configures logging for the project, ensuring that log handlers are only added once to prevent duplicate log entries if the module is imported multiple times.

Setup is resilient to a read-only or unavailable $HOME: if the log directory cannot be created it degrades to console-only logging instead of raising, so read-only commands (--help, version) stay usable.

CLI (mibare.cli)#

Thin Typer command-line wrapper around the library core.

CLI application for the project.

mibare <repo> is the whole interface: one command, no subcommands. It is a thin wrapper over mibare.core.resolve.resolve() that parses the argument, prints the resolution and maps the outcome onto an exit code.

mibare.cli.app.main(repository, *, platform=None, json_output=False, verbose=False)[source]#

Recommend which mise backend to install a GitHub repository with.

Exits 0 when a backend is found, 1 when none is, and 2 on an error such as input that is not a GitHub repository or a missing or too-old mise.
